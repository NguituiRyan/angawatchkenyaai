# Feature-phone & offline reach — the last mile

The dashboard is for the **lender**. The **farmer** is often on a feature phone in a
low-signal area — so the same risk engine + Credit-Risk score reach them over SMS and,
where there's no signal at all, an offline in-greenhouse alert box. Everything degrades
gracefully (the same philosophy as our labeled mocks).

## Connectivity-resilience ladder
1. **Smartphone / web** → the Streamlit dashboard (lender + connected farmer).
2. **Feature phone + data** → SMS push alerts + pull (status / loan).
3. **Feature phone, no data** → **SMS/USSD** via Africa's Talking (free to the farmer).
4. **No cell at all** → ESP-NOW sensor node → in-house **OLED + LED + buzzer** box.
5. **Cooperative scale** → a shared **LoRaWAN** gateway aggregates many farms → backhaul.

## Two-way SMS (bilingual EN/Kiswahili)
A farmer texts a keyword to the Angawatch number and gets an instant reply, in their
language, generated by the **real** engine + scorer (`comms/sms.py`, `comms/i18n.py`):

| Keyword (EN / SW) | Reply |
|---|---|
| `STATUS` / `HALI` | live greenhouse status + any action alert |
| `LOAN` / `MKOPO` | credit score, band, limit (a loan officer approves) |
| `ALERTS` · `STOP` | subscribe / unsubscribe to push alerts |
| `SW` / `EN` | set language |
| `HELP` / `MSAADA` | options |

Aggregator: **Africa's Talking** (native USSD + cheapest Kenya SMS, free sandbox + web
simulator) — the proven playbook behind DigiFarm, FarmDrive, Apollo. A webhook drives
`handle_inbound()`; the built-in simulator (dashboard "Feature phone & offline" tab) lets
it demo with no external dependency. Consent (Kenya Data Protection Act 2019) is captured
via the opt-in keyword and stored on the farmer (`subscribed`).

> Kiswahili strings are a first pass for the demo and should be reviewed by a native
> agronomist before production.

## Offline alert box (no internet) — `comms/offline_box.py`
A sensor node in the greenhouse radios alerts to a separate in-house box (ESP32 + SSD1306
OLED + buzzer + LED) over **ESP-NOW** (peer-to-peer, no router/internet, ~30–80 m indoors /
150–250 m outdoors). The box shows a short **action-first bilingual** line with colour +
buzzer for low-literacy users (red/long-buzz = act now, amber = caution, green = OK). It
**stores-and-forwards**: caches readings and syncs to `/ingest` when a signal returns.

## IoT hardware path (the real seam is already built)
The node just `POST`s JSON to the existing **`POST /ingest`** endpoint — no backend change.

| Part | Role | ~Cost |
|---|---|---|
| ESP32 | compute | $3–8 |
| 7-in-1 soil sensor (RS485/Modbus) | moisture, temp, pH, EC, N-P-K | $16–127 |
| DHT22 | air temp + humidity | $8 |
| SIM800L (2G) → POST over GPRS | cellular uplink | $5–12 |
| TP4056 + 18650 + small solar | off-grid power | ~$20 |
| **Total / node** | | **~$120–240** |

Notes: leaf-wetness is **derived** from DHT22 dew-point (saves ~$100); pheromone **trap
counts are manual** (entered via SMS). **SIM800L is 2G** — plan a SIM7600/LTE migration as
Kenya's 2G sunsets. **LoRaWAN** only pays off at cooperative scale (TTN coverage in rural
Kenya is sparse; needs a gateway).

## Demo vs roadmap
- **Live now:** bilingual two-way SMS + the offline-box simulator in the dashboard, both
  driven by the real risk engine + credit score; `/ingest` ready for a real node.
- **Roadmap:** physical hardware build + field trial; Africa's Talking production shortcode;
  LoRaWAN gateway for cooperatives; native-speaker Kiswahili localization.
